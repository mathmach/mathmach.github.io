## ✨ Why Wind Comic?

Most "AI video" tools give you a disconnected 5-second clip from a one-line prompt. **Wind Comic gives you a finished, fully-assembled vertical video** — script, character or virtual UGC creator consistency, multi-shot visual sequence, voiceover, auto-ducked BGM, beat-synced dynamic subtitles, and a final mp4 — with zero manual stitching required.

It works because it doesn't try to be one giant model. It's an **honest multi-agent pipeline** where each role (Writer, Director, Producer, Character Designer, Storyboard Artist, Cameo Locker, Lipsync, Editor) is a specialist that hands off with strict consistency contracts. Downstream, users can optionally publish directly to social networks (TikTok, Instagram, YouTube) or refine cuts on a collaborative timeline.

```
   "A reborn CEO confronts his cheating ex-fiancee at her wedding."
                                       │
                                       ▼
   Writer ▶ Director ▶ Style Bible ▶ Char Designer ▶ Scene Designer ▶
   ▶ Storyboard (vision-audited) ▶ Video (multi-engine race) ▶
   ▶ TTS (per-character voice) ▶ Lipsync (wav2lip / local 2D / ComfyUI) ▶
   ▶ Editor (j-cut/l-cut + BGM per act + subtitles) ▶ final.mp4

   + Real-time collab timeline (WebSocket presence + PostgreSQL segment locks)
   + Bring-your-own LLM (3 env vars, 0 code change)
   + Production media engines (unified on ComfyUI + Google Gemini)
   + Lip-sync pipeline: viseme track → align score → drift auto-correct → engine render → back into timeline   (v10)
   + Template market: save a hit project → rate / favorite / one-click remix (with its voices)               (v10)
   + Per-project cost attribution + budget guard, four-dimension publish gate                                 (v10)
```

## 🆕 Platform capabilities & quality loop

**Sketch-Lock storyboarding** — every shot first renders a B/W composition sketch, then the final frame is generated _locked to that composition_ (toggle at creation time, or per-shot in the Shot Workshop). Camera language finally survives the diffusion lottery.

**Emotion-driven camera** — shots missing camera movement get one derived from story beats (hook→push-in, chase→handheld, reveal→zoom-in, farewell→pull-out, emotion temperature → push/orbit/crane). Even the Ken Burns degradation follows the intended move.

**Engine matrix, honestly** — self-hosted ComfyUI video pipeline, with base64 first-frame channel for local assets, and an _honest_ fallback chain: a failed shot becomes a labeled animatic, never a still image masquerading as video.

**The quality loop** — ffprobe-powered film health report (aspect/duration/fps/bitrate/audio/degraded shots) per project _and_ per series; batch re-render of degraded shots (2-way concurrent); a season-export health gate so no broken episode sneaks into the compilation; an engine weather bar so you know _before_ you hit generate.

**Round-trip storyboards** — export the pull sheet as CSV / Markdown / print-ready PDF (with character sheet + health appendix), edit in Excel, import it back — changed visual fields offer one-click re-render of exactly the affected shots.

**Writer resilience** — truncated or quote-mangled LLM scripts are salvaged (bracket-stack completion + content-quote escaping) instead of being silently replaced by a template. The real 23KB incident dump lives in the test fixtures.

## 🚀 Highlights · The features competitors don't have

### 1. **Multi-agent pipeline, not one black-box model**

Director plans the story → Writer drafts dialogue under McKee structure → Style Bible Frame locks the look → Character Designer extracts an 8-dimension **DNA signature** of each character → Storyboard renders with Vision Audit (auto-regen on <70 score) → Video producer renders through ComfyUI → Editor cuts j/l-cut on emotional beats and burns subtitles.

### 2. **The visual coherence trick — Style Bible Frame** (v2.20)

We render **one canonical "key art" frame from the Director's plan**, then pass it as the first `--sref` of every subsequent storyboard render. Net effect: all 6 shots feel like they came from the same show, not 6 random disconnected runs. (Most competitors only carry a 2-frame rolling chain — shot 6 doesn't know what shot 1 looked like.)

### 3. **9:16 by default + 12 short-drama trope templates** (v2.20 P0.2)

The Writer prompt detects short-drama / comic-drama genres, switches to a vertical canvas and injects proven hook patterns (reborn N years in the past · a public slap + a secret identity · a system notification suddenly sounding · etc). McKee 3-act still backs it; tropes are the surface.

### 4. **Real subtitle burning** (v2.22)

The garbled-text-in-AI-video problem solved properly: we **strip dialogue text** from the video prompt (so the model doesn't try to draw garbled glyphs) + add aggressive negatives (`--no text --no captions`) + post-bake real subtitles with ffmpeg `subtitles` filter using a system font.

### 5. **Character consistency = cref + sref + 8-dim DNA + Cameo Vision Retry** (v2.21 P1.2)

Beyond reference image hacks, we run each character's turnaround sheet through Vision LLM to extract structured features (eye shape / jaw angle / hair style / signature outfit etc.), then inject as natural-language anchor into every shot prompt. Combined with cameo-vision-retry: if a shot's character match scores <75, we auto-regen with boosted cw.

### 6. **Logic-Pro-style multi-track timeline with real-time collab** (v3.1.1–v3.1.3)

- 3 tracks: shots / BGM / subtitle
- **Real BGM waveform** decoded via Web Audio API (not procedural)
- **Drag-to-retime + edge handles** to resize duration
- **Auto-snap to neighbors** within 0.4s threshold + hard-clamp on overlap
- **Real-time multiplayer**: WebSocket presence server paints other users' cursors live, presence avatars show which tab each collaborator is in, PostgreSQL segment locks prevent two people editing the same segment
- **Project invites** with viewer/commenter/editor role gating

### 7. **Lipsync that actually works** (zh / en; needs a public video URL + audio ≥ 2s)

A wav2lip HTTP service for talking heads, with a local 2D pass and ComfyUI as auto-fallback. The pipeline strips dialogue from the prompt so the model only generates lip _motion_; we then sync the lips to the TTS audio in post. **Real-machine limits:** dialogue audio must be ≥ 2 seconds and the source video must be reachable at a public URL; ja/ko/ru currently degrade to no lip-sync (honest skip, surfaced in the engine-weather panel).

### 8. **Conflict / reversal / cliffhanger pacing audit — v2** (v2.21 P1.1 → v12.275)

After Writer finishes, we score each shot 0-10 on a Chinese-conflict-word dictionary + detect emotional polarity reversals + cliffhanger keywords.

**v12.275 turned scoring into diagnosis.** An average score hides the difference between a story that _builds_ and one that peaks in shot 1 — `[1,2,4,9]` and `[9,4,2,1]` both average 4. So v2 adds four things the average cannot see:

- **Conflict-curve shape** — least-squares slope + peak position + peak prominence, classified as `escalating` / `flat` / `front-loaded` / `no-climax`.
- **Drag-segment localisation** — names the exact shot range (e.g. "shots 3–5") where conflict flatlines, instead of reporting one global number.
- **Opening density** — the first third is audited separately, because completion rate is decided there.
- **Duration rhythm** — v1 never looked at `duration`; v2 flags both uniform-length monotony and long-take pile-ups.

Every finding points at the shots to change. All pure functions over existing fields — **no extra LLM calls, no added cost**.

### 9. **Google Gemini Native Intelligence** (v3.1.3)

Every text-LLM call (Director / Writer / Vision / Audit) connects natively to Google Gemini (or custom endpoints if desired). Edit environment variables in `.env.local` with zero code changes. ## 💰 Market and commercial value (verified 2026-08-07)

> Every figure in this section comes from online research (iiMedia, DataEye, Chinatopbrand, Qianzhan,
> Xinhua, published NRTA documents and others), **including facts that are unfavourable to this project**.
> We think spelling out the sector's real economics is more useful than stacking up a pretty TAM.

### Market size

| Metric                         | Value                                                                                                                                                | Basis                                       |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| The Chinese micro-drama market | **passed ¥100B in 2025** (¥50.4B in 2024, +35%)                                                                                                      | full-year output value                      |
| 2026 forecast                  | roughly **¥120B**, with MAU holding around 718M                                                                                                      | multiple firms agree                        |
| **The AI comic-drama segment** | **¥18.98B in 2025, +276% year on year**; over ¥85B by 2030E                                                                                          | iiMedia Research                            |
| AI penetration                 | **of the 128,000 titles launched in Q1 2026, about 122,000 involved AI (>95%)**                                                                      | AI is already the default production method |
| Overseas                       | roughly **$4B** of output value in 2025, with **$2.03B (+115%)** of in-app purchases across both app stores; Chinese players hold about 80% globally | ReelShort $432M / DramaBox roughly $370M    |

### Cost reduction: what this pipeline is measured against

|                 | Traditional live-action micro-drama | The AI pipeline                               |
| --------------- | ----------------------------------- | --------------------------------------------- |
| Cost per title  | **¥300K–1.5M** (premium ¥1.5M–3M)   | **¥20K–300K** (pure AI comic drama ¥20K–100K) |
| Schedule        | 15–30 days                          | 1–30 days                                     |
| Team            | a crew of 40+                       | 3–10 people                                   |
| Cost per minute | around ¥10,000                      | **¥100–4,000**                                |

**An overall 80–90% cost reduction.** The extreme case, "The Little Carpenter of Anhui", cost ¥2,900 to
produce and returned about ¥500,000 (an ROI of roughly 170×).

### ⚠️ But three things must be said plainly (they decide what this project should sell)

**① Production is only 7.5% of total cost; user acquisition is 70–85%.** By Qianzhan's breakdown: platform
ad buying 82.5%, production 7.5%, actors 5%, script 1.5%. **That means "halving production cost again" has
almost no effect on a project's P&L** — any tool whose only pitch is "cheaper output" has a very low
ceiling.

**② The unit economics are already thin.** CPM fell from roughly ¥60 per thousand in H2 2025 to
**¥15–30 in 2026**; a standard ROI is only **1.03–1.07** (better for Southeast Asian export, 1.2–1.5).
**Around 90% of AI short-drama companies are losing money**, the hit rate for AI comic drama is under
**0.1%**, and the top 5% of projects take 70% of the industry's profit.

**③ Platforms are downranking "purely AI generated".** In 2026 Douyin, iQiyi and Tencent Video introduced
new tiered revenue-share policies that **cut the guaranteed resources for fully AI short dramas with no
live-action performers**, favouring "live action + AI collaboration" instead.

### So this project's value proposition has to be these three things (not "saving money")

1. **Raise the completion rate and the quality floor, to reach for that <0.1% hit rate.** Pacing and
   conflict audits, per-shot Vision QC with automatic regeneration, character consistency (DNA + embedding
   cosine), publish preflight — all of it **reduces wasted footage**, and the waste rate is what actually
   kills this business.
2. **Deliver into a professional edit suite, supporting the "live action + AI collaboration" the platforms
   are now favouring.** EDL / FCPXML / **real binary AAF** (MS-CFB, for Avid) export — AI-generated
   material can enter a human editor's project rather than only shipping as a finished cut. **This is a gap
   shared by every competitor we have examined.**
3. **Self-hosting + open source + BYO keys, serving B2B production and brand customization.** The industry
   is shifting from consumer ad buying to tourism and brand customization contracts (deals worth hundreds of
   thousands to millions of yuan), and those clients have hard requirements that **data never leaves their
   own environment** and that **costs stay controllable** — something closed-source SaaS structurally
   cannot offer.

### 🚨 Compliance: a hard deadline from 2026-09-01 (less than a month away)

The NRTA's "Administrative Measures for the Development of Micro-Dramas" **take effect on 2026-09-01**:

- micro-dramas generated or assisted by AI must be labelled "AI-created" or "AI-assisted production" in a
  **prominent position in every episode**, with **no blurring or shrinking of the type**;
- the video's **metadata must embed AI generation provenance**;
- **a three-level classification filing** — tiers 1 and 2 require provincial-level or higher review approval
  before broadcast, and without a filing a title may not be distributed or entered for awards.

> **This project's current status (disclosed honestly)**: the measures bind **content broadcasters and
> distributors**, not the open-source tool itself; this project does not operate content, so they do not
> apply directly. What the tool side already provides: the mandatory `aigc_info` tag on Douyin direct
> publishing from v12.222 + a structured AI declaration in the export bundle (422 until it is confirmed) +
> a badge on the finished film. The badge is one customizable
> watermark — which videos carry it is decided by the plan (`pricing_tiers.limits.watermark`), the text
> comes from `WATERMARK_TEXT`, `WATERMARK_AIGC=1` folds the AI-GENERATED label into that same stamp
> rather than adding a second one, and `WATERMARK_FORCE=1` stamps every plan for compliance. **Not yet provided**: writing the provenance fields into the video metadata.
> **If you plan to distribute your films on mainland Chinese platforms, enable the badge yourself and
> complete the filing and labelling each platform requires** — compliance responsibility sits with the
> operator.

## 🆕 Core workflows — pull-replicate, smart editing & management

Real puppeteer captures of the running app (`bun scripts/capture-screenshots.ts`). The core capabilities:

- **AI pull-sheet replication**: the five-column pull sheet as ground truth (factory parameters, not an AI guessing from the image) · ffmpeg segmentation of external video + BYO Vision labelling · the replacement workbench (global swaps at the "turn everyone into cats" level) + starting a replica (preserving the original's shot structure and durations) · replication fidelity comparison · save as a private template.
- **Project/asset management**: delete and unpublish in My Projects / My Assets (cascading cleanup + owner guards).
- **Model radar**: one-click scanning for each API's newest models + automatic upgrades within a family (four guardrails + rollback).
- **The three hook-audit metrics**: the first-3-seconds hook / the episode-ending cliffhanger / the BGM beat alignment rate.
- **Smart editing**: beat-aligned cutting (cut points snap to the music's beats) · the emotional rhythm curve (peak shots breathe / action shots cut fast) · emphasis (key shots are never compressed + steadier transitions) · transition taste (the transition follows the relationship between shots) · **one-sentence style control** — "fast-paced and pumped" / "slow and lyrical" in one line adjusts the pacing strength and how hard or soft the transitions are; without a key it uses rules, with a key an LLM parses the free text.
- **Preview audio**: clip previews overlay the voiceover (a silent bare clip + a synchronized voice track) + a health check and self-heal on the finished film's audio (ffprobe detects a missing stream and adds a track).
- **Character/asset consistency & global asset memory**: high-dimensional character feature vectors + cross-scene consistency — name normalization fixes missed DNA injection · DNA and scene anchors persisted (reused across reruns and restarts, so early shots are never missed) · text embeddings + in-memory cosine retrieval · "similar characters" recommendation with one-click reuse at the character-creation entry point (preventing duplicates and cross-episode drift) · **identity drift detection** (per-shot visual embedding cosine distance flags the outlier drift shots). Throughout, it **works without a key on the deterministic floor (exact name + text matching) and is enhanced by vectors with one**, degrading honestly.
- **Security hardening**: strict JWT security with zero hardcoded fallbacks (per-process random secret; legacy secrets voided).

```bash
# Edit apps/web/.env.local:

#   GEMINI_API_KEY=...

                           # Artifacts live in object storage, not on disk: the four S3_* values

bun run dev                # migrations + catalogue seed, then Next.js on :3000
                           # and the WebSocket presence server on :1234 in the same terminal

# 4. open http://localhost:3000 and create your first short film
```

```
packages/          db (Prisma schema + migrations + repositories) · types · zod · ui (components

                   events · storage · lib · telemetry · tsconfig

openspec/          spec-driven change proposals

turbo.json         task graph · biome.json  lint/format · Dockerfile  production image
```

The schema is **not** under `apps/web`: it lives in `packages/db/prisma`, and the Prisma client is
generated into `packages/db/src/generated`.

**Root commands** (all of them run through Turbo, except `lint`, which Biome runs directly):

| Command                                             | What it does                                                             |
| --------------------------------------------------- | ------------------------------------------------------------------------ |
| `bun install`                                       | Installs every workspace and generates the Prisma client                 |
| `bun run dev`                                       | Migrate → seed catalogues → Next.js (:3000) + WS presence server (:1234) |
| `bun run build` / `bun run start`                   | Production build / serve                                                 |
| `bun run test`                                      | Vitest suite (needs a reachable Postgres)                                |
| `bun run typecheck`                                 | `tsc --noEmit`, must be 0 errors                                         |
| `bun run lint` / `bun run check`                    | Biome lint · the full pre-PR gate                                        |
| `bun run db:migrate` / `bun run db:seed`            | Pending migrations · everything a fresh database needs                   |
| `bun run db:seed:catalogs` / `bun run db:seed:demo` | Just the reference catalogues · just the demo account                    |

To work from inside a workspace, use `bun run --cwd apps/web <script>` — `dev`, `build`, `test`,
`typecheck` and `lint` all exist there. The database commands do not: the schema belongs to `@wind/db`, so
`db:migrate`, `db:generate` and the seeds run from the root or from `packages/db`.

**The API is oRPC.** One procedure per operation in `apps/web/server`, served over two protocols from the
same definitions — RPC for the typed client, OpenAPI for plain HTTP — plus a separate key-authenticated
public surface whose generated document is at `/api/public/openapi.json`.

**Minimum LLM**: any model ≥24B parameters that responds in JSON. Google Gemini 2.5 Flash and Pro are natively supported.

**Optional engines** (graceful fallback when missing):

- `GEMINI_API_KEY` — Google Gemini LLM + Gemini image
- `COMFYUI_URL` — self-hosted ComfyUI for video, image, music and lip-sync workflows
- `LIPSYNC_API_URL` — a wav2lip-compatible lip-sync service
- `GEN_CONCURRENCY` / `GEN_CONCURRENCY_VIDEO` · `_STORYBOARD` · `_SCENE` — per-stage generation concurrency (default 2, max 8). ⚠️ Higher _video_ concurrency is faster but weakens keyframe-chain continuity (shot N pulls shot N-1's last frame) — keep it low (1–2) when cross-shot continuity matters.

### ⚠️ Redistribution notice — bundled binaries are not all MIT

**Wind Comic's own source is MIT.** But three npm dependencies ship pre-built binaries under copyleft licenses. This does **not** affect the MIT status of this repository, and it does not affect you if you simply run or fork the source. It **does** matter the moment you redistribute a bundle that embeds those binaries (a Docker image, a desktop build, a hosted appliance you hand to a customer):

| Dependency                           | License              | What you must do when redistributing a bundle                                                                                                                                                      |
| ------------------------------------ | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ffmpeg-static`                      | **GPL-3.0-or-later** | **Strongest constraint.** Ship the GPL-3 text and a written offer for the corresponding FFmpeg source — or drop the dependency and point `FFMPEG_PATH` at a system ffmpeg you obtained separately. |
| `lightningcss` (+ platform binaries) | MPL-2.0              | File-level weak copyleft. Unmodified use/redistribution carries no extra duty; only if you modify its MPL-licensed files must you publish those files.                                             |
| `@img/sharp-libvips-*`               | LGPL-3.0-or-later    | Dynamic linking does not infect your code. On redistribution you must let end users replace/relink the library and point them to its source.                                                       |

CI enforces this: [`scripts/license-check.ts`](https://github.com/ChrisChen667788/wind-comic/blob/main/scripts/license-check.ts) scans the **production** dependency tree every run and **fails the build** if a copyleft dependency appears that is not registered in the table above — so a new GPL dependency can never slip in unnoticed.
